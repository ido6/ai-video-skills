# Previs (Blender blockout) → photoreal Seedance 2.5 video — playbook

Source: Ido's playbook "01-previs-to-ai-playbook" (2026-10-06), distilled from three research reports
(full reports with per-claim links live in the project `research/` folder). Model: Seedance 2.5. Main platform: Higgsfield.
Camera/composition decisions live in the `cinematography` skill → `references/camera-directing-playbook.md`.

## Confidence tags (keep them — never present a guess as fact)

| Tag | Meaning |
|---|---|
| **[official]** | ByteDance docs (BytePlus / Volcengine / official prompt guide) or the platform's docs |
| **[field]** | Reports from creators/studios who worked this way |
| **[inference]** | Conclusion from combining sources. Untested |
| **[unverified]** | No reliable source. Test before relying on it |

Nothing here has been tested in our own generations yet. First tests to run: §15.

## 1. Who controls what

Seedance 2.5 officially supports this exact method: **blockout reference** ("white model"). A video of simple geometry supplies motion, camera and timing; separate images supply the look. **[official]**

| What | Controlled by | Why |
|---|---|---|
| Camera position, move, framing size, pace | **blockout video** | Reference video is stable across runs; text camera description drifts run to run |
| Subject paths, entrances/exits, timing | **blockout video** | same |
| Face, hair, build | **identity image** (one close-up) | Model has no memory; every generation is born from the references |
| Wardrobe | **wardrobe image** (full body) | |
| Architecture, materials, light | **location plate** | "Wrong light in the location image is the most common reason a video looks fake" **[official, Higgsfield]** |
| Product shape, glass, cap | **real product photos** | |
| Label text | **post** (composite / label replace) | Text accuracy not guaranteed **[official]** |
| Hand actions, expressions, gaze | **text** | Pawns have no hands/faces, blockout can't show it |
| Sound | **text** or post | |
| What must not change | **text: lock lines** | |

**Derived rule:** never describe in text what the blockout already defines. Double-describing motion/camera can conflict with the reference. **[official]**

## 2. Hard limits

| Item | Value | Source |
|---|---|---|
| Generation length | 4–30 s, **whole seconds only** | official + Higgsfield |
| Resolution | 480p / 720p / 1080p. No native 4K in 2.5 (Higgsfield 4K = upscale) | official |
| fps | 24 | official |
| Aspect | 21:9 to 9:16 | official |
| References | up to 30 images, 10 videos, 10 audio | official |
| Reference video | 2–30 s each, 30 s total, 24–60 fps, ≥480×854, ≤200 MB | official |
| Reference image | 300–6000 px per side, ≤30 MB. **Not larger than output resolution** (else fingerprint-like texture) | official |
| Prompt length | ≤ ~1,000 English words; beyond that details drop | official |
| Negative prompt | **No field.** Only sentences inside the prompt | official |
| Draft | 480p draft, finish at 1080p with same params (Higgsfield: within 7 days) | official + Higgsfield |
| Audio | Generated by default, can be turned off | official |
| Faces | Direct upload of real faces blocked in official API. Higgsfield runs an eligibility check on character Elements | official / Higgsfield |

**Consequence:** a 2–3 s shot must be generated at ≥4 s and trimmed in the edit. Export every control clip from Blender in whole seconds, ≥4 s, with a "tail" of real animation at the end.

## 3. Pipeline stages

Order all sources agree on: **lock references before generating in volume, stills before video.** A flaw approved at sheet stage is paid for in every later shot.

| # | Stage | Output | Done when |
|---|---|---|---|
| 0 | Brief & constraints | One page: platforms, aspect, length, product, AI-disclosure plan | Owner approved |
| 1 | Script lock | Script with seconds per beat | Every beat has a visible end state |
| 2 | Shot list | Table: size, lens, move, action, end state, risk | One camera move + one main action per shot. Hardest shot flagged |
| 3 | Previs / blockout | Clean control clip per shot, stills, top view, .blend | Clean clips, real scale, ≥4 s |
| 4 | Animatic | Clips cut to final length | Story reads with pawns. Lengths frozen |
| 5 | Techvis | Per shot: lens, camera height, speed, screen direction | Values written once, repeated verbatim |
| 6 | Look development | Look bible: palette, light plan, lens feel, one grey for sheets | One master still approved as target |
| 7 | Reference sheets | Characters, wardrobe, product, location | Each passed its check (§5) |
| 8 | Motion test | Low-res draft of hardest shot + candidate plates | Hard shot feasible, or redesigned |
| 9 | Keyframes | Photoreal start frame per shot | Matches previs frame + sheets |
| 10 | Video generation | Several logged takes per shot | One take passes. Stop rule applied |
| 11 | Selection & frame check | Chosen take with in/out points | Clean frame-by-frame |
| 12 | Repair | Fixed shot | Flaw gone, nothing else changed |
| 13 | Product & text composite | Hero/label shots with real product | Label matches real product 100% |
| 14 | Upscale | Masters | No new artifacts, skin not waxy |
| 15 | Edit | Picture lock per animatic | Exact length. State + screen direction hold at every cut |
| 16 | Color & texture | Graded master, grain last | Neighbouring shots match |
| 17 | Sound | Mix | Hits in sync |
| 18 | Final QC & delivery | Files, disclosure settings, prompt archive | Checklist signed |

## 4. Blender previs rules

### Shape
1. **Limbless pawns.** Officially recommended level is coarse geometry ("coarse blockout"). Half-animated limbs come out stiff or misread. **[official]**
2. **Add detail only where you want control.** Detailed proxies get reproduced literally (a crouching proxy came out as crouching riders). **[field]**
3. **Real scale.** Silhouette and scale must be right — doors, heads, human height. **[field]** A double-size head makes every close-up tighter than intended.
4. **Story-critical props** (tray, bottle, glasses) get their own simple primitive so their placement is controlled. **[inference]**
5. **Floor and horizon.** Without ground, objects generate floating in space. **[field]**

### Colour & light
6. **Neutral grey set.** Reference hues bleed into the image; a coloured room is the riskier part. **[field]**
7. **One flat colour only for main characters and props.** Official examples map proxies by colour or shape ("the red model", "the tall cylinder"). **[official]**
8. **Every proxy identifiable by two cues** (colour + shape/height/position) — one report says colour-only mapping is unreliable. **[field, conflicting reports]**
9. **Does pawn colour leak into wardrobe? [unverified].** If worried (red pawn for a woman in a white dress), paint the pawn the wardrobe colour.
10. Blockout lighting is flat, so write that light is not inherited from it. If you want light to carry over, light it deliberately and say so. **[official]**

### Clip cleanliness
11. **Nothing drawn on the frame:** path lines, gizmos, grid, camera cones, frame counter, captions. All of it leaks; burned-in text beats "no subtitles". **[official]**
12. **Nothing moves unless it should.** Background motion in the reference gets copied. **[field]**
13. **No audio track** in the clip so nothing is inherited. **[inference]**

### Camera & timing
14. **One dominant camera move per shot.** Stacked moves read as instability. Split complex moves into two shots. **[official for 2.0, field for 2.5]**
15. **Lens is baked into the clip.** The focal length chosen in Blender is what you get — choose it as a cinematography decision (see `cinematography` skill). **[inference]**
16. **Pace in the clip beats text.** Proxies move at the real speed you want. **[field]**
17. **Shake:** bake only slow, low handheld (shoulder float, small corrections). Fast shake: ask in text or add in edit. No numeric threshold in any source. **[inference]**
18. **One clip per shot.** Cuts inside one generation hold worse, and 2.5 tends to cut even when asked for one take. **[field]** Officially a blockout with cuts is supported, but less predictable for 2 s shots.

### Clip spec
19. 24 fps, final output aspect, 720×1280 or 1080×1920, 4–10 s, whole seconds.
20. **Clip length = generation length.** Behaviour when the clip is shorter than output is undocumented. **[unverified]**
21. Also export: a still of the empty set per camera direction, and a top view. Those are the location plan.
22. Blockout `first.png` **is not a start frame.** It is a composition input to the image model, which produces the real start frame from it.

## 5. Sheets

### Applies to all
- **One flat grey background for the whole project** (one hex, not white, not black, no gradient). Grey tested better than white/black. **[field]**
- Even light, no hard shadows. A contact shadow on a sheet is baked lighting that shots inherit.
- **Sheets leak:** grey background, panel borders and layout can become the set. For every reference also write what *not* to take from it. **[official]**
- Separate images per view align better than one collage. **[field, reported as official guidance]**
- Fix a small flaw with a targeted one-line edit, not a re-roll. Every edit pass softens skin.

### Character
| Item | Rule |
|---|---|
| Views | Face close-up, full body front, full body back. Minimum: one clear face + one full body |
| **Only one readable face** | If full-body panels also show faces, the model averages them or takes the face from the small figure. Crop heads off body images fed to the video model |
| Expression | Neutral, mouth closed |
| Hands | Empty. A prop is a separate reference |
| Wardrobe | Separate sheet: fabric, colour, cut, closures, how fabric moves. Simplify outfit to silhouette + one signature feature |
| Description | One fixed identity sentence repeated **word for word** in every shot. Rewording creates a different person |
| How much to feed | Only what the shot uses. Fewer and consistent wins |

**Library vs feed:** library keeps every view. Per shot, feed the video model: one face close-up + one headless body.

### Location
| Item | Rule |
|---|---|
| Master plate | Empty of people, three-quarter view (not frontal), light "pinned": direction, height, quality |
| Reverse angle | Separate named asset, one per side of the 180° line. Generate it with the master attached, plus a list of what carries over (materials, palette, grade) and what is *not* in the new angle — otherwise the model invents a second doorway |
| Selection | **By light first**, then "is there room for blocking": clean action corridor, clutter at edges, no strong colour cast |
| Link to previs | Previs frame = structure reference; style image = material reference. Blender top view is the binding plan **[inference]** |
| Test | Run finalists in a short video generation before locking |
| Exposure | Match all plates to the master, else the difference reads as a lighting change at the cut |

### Product
| Item | Rule |
|---|---|
| Source | **Real packshot photos of the actual product.** Never regenerate the product |
| Views | Front, side, three-quarter, back, label macro, scale context. Bottom only if it gets flipped |
| In prompt | One line per view, then: "all views are the same object, and only one exists" **[official]** |
| Scale | Words like "small" don't hold. State size relative to the body, arithmetically right for the character |
| Label | Generated product OK in wide/medium. **Any frame where the label is readable: real product via composite or label replace.** Plan it upfront, not as a fallback |
| Split rule | Never put readable label + hand action on product + effect (spray) in one shot. One shot proves the action, another the label |

## 6. Keyframes: hybrid approach

No controlled comparison exists between "start frame then animate" and "straight to video with all refs". **[unverified]** Reports lean hybrid, which is also the officially demonstrated combo:

1. Render shot's first frame from the blockout.
2. Pass it through an image model with the sheets → **photoreal start frame** in the same composition.
3. Check it as a still against sheets + look bible.
4. Generate video in omni reference: start frame declared as first frame, blockout clip as motion/camera reference, sheets attached for anything the frame doesn't show.

Rules:
- **One sentence per anchor image.** Don't combine first and last frame in one sentence. **[official]**
- Build the end frame **by editing the start frame**, not a new generation. **[Higgsfield / fal]**
- Whatever must move should already be visible in the start frame, starting to move. If the action needs something the frame doesn't show, write that it's off-frame and where it enters from.
- Shot where the character isn't in frame 1 (entrance), or platform rejects a start frame with a face: go reference-first, no start frame.
- Locked-off shot (no camera move) can run plain first-frame mode, no reference video.

## 7. Seedance 2.5 prompt

### Order **[official]**
1. **Asset roles:** one line per reference.
2. **One summary sentence:** who, where, what happens, style.
3. **Event** in stages or timestamps.
4. **Closing notes:** what stays constant (identities, head count, wardrobe, prop ownership, spatial directions, light, sound).

Duration/aspect/resolution go in the UI, not the prompt.

### Role lines
- For each asset: **what it gives and what not to take from it.** Not "images 1–4 are the four characters".
- **Upload assets in order of first appearance** and number accordingly — official fix when the first character takes another's look.
- One fixed tag per subject (`<Woman>`, `<Waiter A>`) repeated everywhere.
- Each prop has one owner; character block includes a line forbidding swapping looks, wardrobe, actions or positions between them.

### Blockout declaration (official structure)
1. Declare the video a coarse blockout giving **only** the listed dimensions; don't use its look, materials or set.
2. Map each proxy to a named subject by colour or shape, one line each.
3. Role lines for look images.
4. The event in plain prose, **consistent with what the blockout shows**.
5. Repeat which dimensions are kept from the video.
6. Final look and sound.

### Write / don't write
| Write | Don't write |
|---|---|
| Subjects, scene, look, light | Re-description of a camera move the blockout already defines |
| Hand actions the pawn can't show (spray, set down) | An action twice |
| Action as causal chain: start state, what grips, where force applies, what material does, end state | "more natural", "realistic", "cinematic" |
| Expression as visible behaviour (eyes first, then chin) | Strong emotion words (cause glowing eyes) |
| Visible end state per stage | Edit verbs (edit, add, remove, replace, change to) in a non-edit job — they trigger edit mode |
| Positive description | Generic negative lists |

### Camera & lens in prompt
- Terms that work directly: shot sizes, push in, pull out, pan, track, follow, orbit, tilt, handheld, one-take, locked-off. **[official]**
- Niche term: keep the term and add its visible result. Rack focus: who softens, who sharpens. DoF and motion blur written as visible results.
- Lens, stop, shutter numbers **allowed**, but describing the result is clearer than the number alone. **[official]**
- **Camera body + lens names:** appear in official examples, Higgsfield recommends, but no controlled test shows what they do. **[unverified]** Treat as **look anchor**, never as geometry control.
- **Our practice:** camera + lens written once in the look block, identical in every shot. Number taken only from previs. If the blockout lens is 35 mm, write 35 mm.

### Timestamps
- Whole seconds. Contiguous ranges, no gaps or overlaps.
- A timestamp is a **time budget, not an edit point**. Action may land slightly early/late.
- Too little content in a range invites improvisation; too much causes cuts and dropped events. Windows ≥3 s execute better. **[field]**

### Length & language
- Blockout job is longer than plain image-to-video (mapping + full description), but stay under 1,000 words.
- English. No evidence Chinese works better.

### Working template (one shot)
```
@Video 1 is a coarse blockout reference. Take only the camera position and move, framing,
subject paths, blocking, entrances/exits and timing from it. Do not use its geometry look,
flat colours, grey materials or empty room.
The red pawn in @Video 1 corresponds to <Woman>.
The blue pawn corresponds to <Waiter A>.
The small amber block with the pale cap corresponds to <Perfume Bottle>.
The silver disc corresponds to <Silver Tray>. The pale yellow cylinders are champagne flutes.
The grey pawns are background guests: <N> in total, seated/standing where the blockout shows them.

@Image 1 is the first frame.
@Image 2 defines <Woman>: face, hair and make-up only. Do not use its grey background or framing.
@Image 3 defines <Woman>'s dress and build: cut, fabric and colour only. Do not use its background.
@Image 4 defines <Waiter A>: face and hair only. @Image 5 defines his uniform only.
@Image 6 and @Image 7 are front and three-quarter views of the same <Perfume Bottle>: shape, glass,
gold collar, clear cap and label position. Only one bottle exists throughout.
@Image 8 defines the hotel lobby: layout, materials and light sources only. Do not use any people in it.

Summary: <one sentence: who, where, what happens, register>.

Event: <plain prose, consistent with the blockout: what the hands do, what the face does,
each stage ending in a visible end state>.

Keep from @Video 1: camera position and move, framing changes, subject paths and timing.
Do not add shots. Do not change the shot structure.

Look: <the one look block of the film: camera body + lens as look anchor, stop, depth of field
as a visible result, 24 fps with natural motion blur, the motivated light sources with colour
temperature and direction, grain>.

Sound: <exact list of what may be heard, each tied to its action>. No music, no score.

Consistency: exactly <N> people in frame; one <Woman>, one <Waiter A>, no duplicates; she holds the
bottle in her left hand until <event>; wardrobe, hair and lighting unchanged; real-time pace.
No subtitles, captions, logos or watermarks.
```

## 8. Preventing inventions

No negative field. Pattern that works in official examples: **positive locks + a few targeted bans.**

| Risk | What to write |
|---|---|
| Extra people/objects | Exact head count for the whole clip, and as an end state per stage: who's in frame, who holds what, nobody else enters |
| Duplicate character | "one <Name>, no duplicate or twin, one instance per frame". Tie the character to its image at every mention. Single-person reference images |
| Face/wardrobe drift | Strict-match line per subject, head-only reference, do-not-interchange line |
| Unwanted cuts | Don't overfill a time range. "one continuous take". With blockout: "do not add shots" |
| Unwanted slow motion | No official statement of such a bias in 2.5. What helps: specific action verbs, pace words, blockout moving at real speed. "real-time 24 fps, no slow motion" is common but untested |
| Floating camera | One move with a start and end — or, better, the move comes from the blockout |
| Lighting changes | Name the source + direction, and list lighting in the consistency block |
| Subtitles | "no subtitles" officially supported. Ensure no text in any reference. Higher risk in 9:16 |
| Logos/watermarks | Explicit line |
| Music | See §12 |
| Object vanishing behind occluder | Write the occlusion and the reappearance with the same identifying details |
| Hands merging with prop | One hand, one object, named grip point, one action |

**Known behaviour:** 2.5 fails by "over-execution" — it tries to perform nearly every instruction, then misuses a reference or breaks a global constraint instead of quietly dropping a shot. **[field]** So: fewer, clearer instructions.

## 9. Product & label

- Text errors are a known failure (swapped/added/dropped letters). Official line: for signs, product specs, anything that must be exact, combine prepared reference material, generation **and post**. **[official]**
- Repair path: subject-replacement template in edit mode swaps an object for one from a reference image while keeping everything else. Higgsfield: region edit.
- "Composite + keyframe" for glossy product: product pixels are never generated. Cut the real photo to transparent PNG, generate an empty plate, place the product, animate between composited stills. **Limit:** assumes product stays put; a moving camera or something passing in front brings inventions back.
- Even a composited real label smears at edges with strong nearby motion → **hero shot stays calm**.
- Moderation: on Higgsfield, reference images with a visible logo can trigger an IP block, even for your own brand. There's an ownership-declaration button. **[Higgsfield]**

## 10. Cross-shot consistency

1. **Independent clips per shot from the same locked references**, joined with straight cuts, ideally on action. Don't chain last frame across a real cut: each round softens texture and shifts palette.
2. **Absolute values, identical in both prompts.** Referring to "the previous shot" doesn't work — no generation sees the other.
3. **State only accumulates:** broken glass stays broken, bottle stays on the tray.
4. **Screen direction written as a lock:** who enters from which side, which side of the line the camera stays.
5. **Change one variable per attempt.** Most effective habit per Higgsfield.
6. **One model version per film.** 2.0 and 2.5 have different aesthetic defaults.
7. **Seed:** weak, platform-dependent control. References do the work.
8. **Grade to one master still** at the end to unify clips with slight colour drift.
9. A 1–1.5 s "empty beat" of location only gives a clean cut point when needed.

## 11. What makes it look filmed (by source frequency)

1. **Light chosen at the still stage.** Soft stays soft, subject lit, exposure doesn't kill the frame.
2. **Motivated, specific light:** named sources, how light meets surfaces. Light haze makes light visible.
3. **Physics written as image:** what moves, where, at what pace, with acceleration; how clothes and hair react. Mass needs weight and contact shadow.
4. **Lens and DoF** in photographic terms. ~47° field of view feels natural.
5. **180° shutter motion blur.**
6. **Imperfect handheld:** float and small corrections, not a hovering camera.
7. **Skin texture:** ask for pores and fine texture. Production language, not "hyperrealistic 8k".
8. **Behaviour:** people react, not just stand. Blink, swallow, breathe.
9. **Location not symmetric, not too clean.**
10. **Restrained grade**, one palette.
11. **Light softening + grain in post**, grain last. Amounts conflict across sources — set by eye at delivery size.
12. **Real pace.** Unintended slow motion is a giveaway.
13. **Avoid model weak spots** when not needed: complex hand actions, expressions straight into lens.

## 12. Sound

- 2.5 generates audio with the image (mono). Can be off.
- Separation syntax: `( )` music, `< >` SFX, `{ }` dialogue. **[official]**
- **Music creeping in despite "no music" is a documented problem.** Fix: audio policy at the top listing exactly what may be heard, a detailed ban (music, BGM, score, instrumental, melody, synth, ambient pad), and repeat the constraint at the end. Never write "no music" inside round brackets — it reads as a music instruction.
- Tie every sound to an action or time.
- Words about water, waves or echo can cause bubbling/hissing artifacts.
- Alternative: generate silent, build sound in post.

## 13. QC

### Method
- **Frame-by-frame in an editor**, on the downloaded file, not the preview. A clip can look fine at speed and hide one broken frame.
- Check **true frame rate.** Output can return with duplicated frames (effective 12–18 fps). Regenerate such a hero shot.
- **Stop rule: same flaw in every take of a batch = the problem is the prompt or source.** More takes waste credits. Stop at first repeat, fix still or prompt.
- Before discarding a take, mark 1–3 usable seconds in it.
- Most flaws appear mid-clip. Watch the whole thing before changing anything.

### What to check
| Area | Look for |
|---|---|
| Face | Same person as sheet in every frame, no averaging to generic, stable eyes/teeth |
| Hands & limbs | Finger count, no merged/orphan hands |
| Body & walk | Weight transfer, heel first, one foot grounded, no sliding |
| People | Head count matches, no background duplicates |
| Wardrobe & hair | Same garment, length, colour, closure. Continuous hair state |
| Product | Silhouette, proportions, cap, liquid colour, label position |
| Text | No warped signage, third-party marks, subtitles |
| Physics | Gravity with acceleration (not constant speed), contact shadows, plausible liquid/glass |
| Action completion | Action finishes and settles before the cut. No snap-back to start pose |
| Performed action | Object actually changes when hands act on it |
| Space | Architecture matches plate. No invented doors |
| Camera | Move matches previs. One dominant move |
| Speed | Real pace |
| Stability | No flicker, texture boiling, background warping |
| Light & colour | Direction + time match master plate. No cast inherited from a reference |
| Reference leak | No grey background, panel borders, pawn shapes, blockout colours |
| Neighbours | State, screen direction, eyeline, exposure match shots before and after |

### Repairs
| Flaw | First step | Fallback |
|---|---|---|
| Same flaw every take | Fix prompt or source asset | Redesign shot |
| Wrong light / tint / architecture | Fix or replace still, regenerate | New plate chosen by light |
| Identity drift | Strengthen identity reference, reattach | Region edit on face |
| Small wrong area in good take | Region edit or re-shoot a segment | Inpaint keyframe, regenerate |
| Start/end don't connect | First/last-frame bridge | Cut on action |
| Wrong label | Composite real label | Replace shot with product composite |
| Soft but correct | Upscale | Higher tier generation |
| Duplicated frames | Regenerate | |
| Unwanted slow motion | Rewrite with pace + verbs, check previs speed | Retime in edit |
| Plastic skin | Skin-texture clause in prompt, soften + grain in post | |

## 14. Faces, moderation, legal

- **Faces:** official API forbids uploading real faces; even AI faces may be classified real. Higgsfield shows face refs and Soul ID in use, but character Elements go through an eligibility check. **Behaviour differs per platform and changes. Check on the day.**
- After a safety rejection, never retry the same wording.
- **AI disclosure:** EU (AI Act Art. 50, in force from 2026-08-02), YouTube, Meta and TikTok require labelling realistic synthetic content, each with own rules. New York requires disclosure when an ad features a "synthetic performer". Decide per platform and territory.
- **Likeness of a real person:** written consent covering AI generation, territories and term. Fully invented faces avoid the likeness question but trigger disclosure where it exists.
- **Product accuracy:** an image misrepresenting the product is misleading regardless of how it was made. Check backgrounds for brands, artworks, a recognisable real hotel.
- Keep a log of prompts, sketches, edits.

Orientation, not legal advice.

## 16. One-page checklist

**Brief:** platforms + aspect · product · disclosure plan · likeness route (invented face or consent).
**Script:** visible end state per beat · total length fits.
**Shot list:** one move + one action per shot · lens per shot · hardest shot flagged · label-readable shots flagged.
**Previs:** real scale · limbless pawns · grey set · proxy identifiable by two cues · key props as primitives · real pace · no overlays · output aspect · 24 fps · every clip ≥4 s whole seconds · one clip per shot · top view + still per direction.
**Animatic:** runs at final length · lengths frozen.
**Techvis:** lens, height, speed, screen direction per shot, written once.
**Look bible:** palette · light plan with sources · lens feel · one grey for sheets · one master still.
**Sheets:** character: grey, even light, neutral, face close-up + body front/back, one readable face, separate images, wardrobe separate · location: empty master with pinned light, reverse as separate asset, chosen by light + blocking room · product: from real photos, every side the camera sees, label macro.
**Motion test:** hardest shot + candidate plates in draft.
**Keyframes:** start frame per shot from previs frame + sheets · checked as still · real product where label is readable.
**Generation:** role + exclusion per reference · camera not re-described · low draft, high finish · takes logged · stop on repeated flaw.
**Selection:** frame-by-frame · frame rate · §13 checklist.
**Repair:** still before video · region edit before re-roll · one variable per attempt.
**Product composite:** label vs real product 100%.
**Upscale · edit · colour (grain last) · sound.**
**Delivery:** checklist on final file · third-party marks · AI disclosure per platform · archive.
